# plugins/ —— the unified ZhuYe plugin directory

<p align="center">  <a href="README.md">中文</a> · <b>English</b>  </p>

All plugins bundled in the repo live here, for easier management,
review, and distribution. Each subdirectory is a complete plugin
(entry point: the `plugin.toml` manifest) and can be installed
directly:

```bash
# Install from the repo path (user scope, into ~/.zhuye/plugins/cache/)
zhuye plugin install plugins/<directory-name> --scope user

# Enable (written into [plugins].enabled_plugins in ~/.zhuye/config.toml;
# note that the <name> part of the id comes from the manifest's name, not the directory name)
zhuye plugin enable <manifest-name>@inline
```

For an explanation of the plugin mechanism (manifest format, the six
capability types, `${PLUGIN_ROOT}` expansion, hot reload) see
[`docs/plugins.md`](../docs/plugins.md); for user-oriented content like
install / enable / marketplace / troubleshooting see
[`docs/plugins.md`](../docs/plugins.md).

## Existing plugins

| Directory name | Manifest name (id) | Purpose |
|---|---|---|
| [`plugin-demo/`](plugin-demo/) | `demo` | Full-capability demo: one minimal runnable sample for each of the six capability types (commands / sub-agents / skills / hooks / MCP / WASM) |
| [`computer-use/`](computer-use/) | `computer-use` | Screen / mouse / keyboard control (xcap + enigo; build the binary first) |
| [`git-tools/`](git-tools/) | `git-tools` | git workflow: branch / PR / diff probing + checkpoint snapshots + Stop auto-checkpoint (build the binary first) |
| [`shell/`](shell/) | `shell` | Resident shell session pool: launch processes / read output incrementally / write stdin / kill (build the binary first) |
| [`goal-queue/`](goal-queue/) | `goal-queue` | Goal mode (the goal tool) + FIFO queue mode (the queue tool; gated form, off by default) |
| [`workflow/`](workflow/) | `workflow` | Serial task and agent workflows with WASM nodes (build the server first) |
| [`kms/`](kms/) | `kms` | Local Markdown knowledge base: multi-wiki pagination + grep search + dream consolidation (build the binary first) |
| [`web-search/`](web-search/) | `web-search` | The `web_search` tool (Brave API; gated form, **on by default**) |
| [`notebook/`](notebook/) | `notebook` | The `notebook_edit` tool (Jupyter cell editing; gated form, **on by default**) |
| [`verify-hooks/`](verify-hooks/) | `verify-hooks` | Plugin enable path for the verification / test_runner hook pair (gated, off by default, dual path) |
| [`lsp/`](lsp/) | `lsp` | LSP integration coarse switch and docs (gated; activation is driven by `[lsp_servers]` config) |

⚠️ **The directory name and the manifest name need not be the same**:
the manifest's `name` is required and is used to form the plugin id
(the `<name>` part of `name@marketplace`). Take `plugin-demo` for
example: the directory name is `plugin-demo`, the manifest name is
`demo`, and you enable it with `zhuye plugin enable demo@inline`.

## Conventions

- Binary plugins put their executables in `bin/` (`.mcp.json` / hooks
  reference them via `${PLUGIN_ROOT}/bin/<name>`); the `bin/` content is
  generated by build scripts and not checked in.
- Purely declarative resources (commands / skills / agents / hooks) go
  directly into their corresponding subdirectories.
